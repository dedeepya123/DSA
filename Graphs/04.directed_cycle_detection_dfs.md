# Directed Cycle Detection Using DFS

## 1. Problem Objective

Given a directed graph with `n` vertices and an edge list, determine whether the graph contains a cycle.

- Return `True` if a cycle exists.
- Return `False` otherwise.

A directed cycle exists when we can start from a vertex, follow the directed edges, and eventually return to that same vertex.

Example:

```text
1 → 2 → 3 → 4
    ↑       |
    └───────┘
```

There is a cycle: `2 → 3 → 4 → 2`.

---

## 2. How to Approach the Problem

Before choosing an algorithm, understand the graph and the problem requirements.

### Questions to ask

1. Is the graph directed or undirected?
2. Is the graph connected or disconnected?
3. Are we checking whether any cycle exists or finding the actual cycle?
4. What traversal technique can help us explore paths?

### Graph characteristics

- **Graph type:** Directed.
- **Connectivity:** May be disconnected.
- **Representation:** Edge list converted into an adjacency list.
- **Vertices:** Numbered from `0` to `n - 1`, including isolated vertices.

For a directed edge `(u, v)`, add only one direction:

```python
adj[u].append(v)
```

Unlike an undirected graph, we do not add the reverse edge.

---

## 3. Why Parent Tracking Alone Is Not Enough

In an undirected graph, we used parent tracking to distinguish between:

- The edge leading back to the parent.
- A genuine cycle-forming edge.

But this reasoning does not work for directed graphs.

Consider:

```text
1 → 2 → 3 → 4
    ↑       |
    └───────┘
```

Suppose DFS starts at `1`.

Traversal:

```text
1 → 2 → 3 → 4 → 2
```

When we reach vertex `4`, we encounter vertex `2`, which is already visited.

If we only check whether the visited neighbor is different from the parent, we might incorrectly classify this as a cycle based on parent tracking.

The problem is that in directed graphs, a visited node could be:

- Currently being explored in the active DFS path.
- Already fully explored in a previous DFS path.

These two situations must be distinguished.

**Conclusion:** We need more information than a simple visited set or parent tracking.

---

## 4. Core Intuition: Three States of a Node

We use DFS because it explores a path deeply before backtracking.

While exploring a directed graph, every node can be in one of three states:

| State | Meaning |
|---|---|
| `0` | Not visited / not explored |
| `1` | Currently exploring / part of the active DFS recursion stack |
| `2` | Fully explored / all neighbors processed |

### Why do we need three states?

Consider:

```text
    0 → 1
    ↓   ↓
    2 → 3
```

Edges:

```python
[(0, 1), (0, 2), (1, 3), (2, 3)]
```

There is no cycle.

Suppose DFS explores:

```text
0 → 1 → 3
```

Once DFS finishes exploring vertex `3`, its state becomes `2`.

Then DFS backtracks to `0` and explores `2`.

From `2`, we reach `3` again.

At this point, `3` is already visited, but it is fully explored.

Does this indicate a cycle?

No.

Why?

Because `3` is no longer part of the current DFS recursion path. We are simply reaching a previously completed node.

This explains why a single `visited` set is insufficient.

### The actual cycle condition

If we encounter a neighbor whose state is `1`, we have found a cycle.

Why?

Because that neighbor is still part of the current DFS path.

There is already a directed path from that neighbor to the current node, and now we have an edge back to the neighbor.

This closes a directed cycle.

```python
if state[nei] == 1:
    return True
```

---

## 5. Algorithm

### Step 1: Build the directed adjacency list

For every edge `(u, v)`, add `v` to `adj[u]`.

Do not add the reverse edge.

### Step 2: Initialize the state array

Create a state array of size `n`, initialized to zero.

```python
state = [0] * n
```

### Step 3: Implement recursive DFS

For `dfs(node)`:

1. Mark the current node as `1` (currently exploring).
2. Iterate through every neighbor of the current node.

For every neighbor:

- If `state[nei] == 1`:
  - The neighbor is still in the current recursion stack.
  - A cycle exists.
  - Return `True`.

- If `state[nei] == 0`:
  - The neighbor has not been explored.
  - Recursively call DFS on it.
  - If the recursive call returns `True`, propagate `True` immediately.

- If `state[nei] == 2`:
  - The neighbor is already fully explored.
  - Ignore it and continue checking the remaining neighbors.

3. Once all neighbors have been explored successfully, mark the current node as `2`.
4. Return `False`.

### Step 4: Handle disconnected graphs

Loop through all vertices from `0` to `n - 1`.

Whenever a vertex has state `0`, start DFS from it.

If any DFS call detects a cycle, return `True`.

If all components are explored without finding a cycle, return `False`.

---

## 6. Implementation

```python
from collections import defaultdict


def hasCycle(n, edges):

    # Build directed adjacency list.
    adj = defaultdict(list)

    for u, v in edges:
        adj[u].append(v)

    # 0 = Not visited
    # 1 = Currently exploring
    # 2 = Fully explored
    state = [0] * n

    def dfs(node):

        # Mark node as currently exploring.
        state[node] = 1

        for nei in adj[node]:

            # Back edge to a node in the current DFS path.
            if state[nei] == 1:
                return True

            # Explore an unvisited neighbor.
            if state[nei] == 0:
                if dfs(nei):
                    return True

            # If state[nei] == 2:
            # Neighbor is fully explored.
            # Ignore it and continue.

        # All neighbors have been explored.
        state[node] = 2

        return False

    # Check every disconnected component.
    for node in range(n):

        if state[node] == 0:
            if dfs(node):
                return True

    return False
```

## 7. Dry Run: Graph Containing a Cycle

Consider:

```text
1 → 2 → 3 → 4
    ↑       |
    └───────┘
```

Edges:

```python
[(1, 2), (2, 3), (3, 4), (4, 2)]
```

Assume DFS starts at vertex `1`.

| DFS action | State of active path | Observation |
|---|---|---|
| Visit `1` | `[1]` | Mark `1` as exploring |
| Visit `2` | `[1, 2]` | Mark `2` as exploring |
| Visit `3` | `[1, 2, 3]` | Mark `3` as exploring |
| Visit `4` | `[1, 2, 3, 4]` | Mark `4` as exploring |
| From `4`, reach `2` | `[1, 2, 3, 4]` | `2` has state `1` |

We have reached a node that is still in the current DFS path.

Therefore:

```python
return True
```

The cycle is:

```text
2 → 3 → 4 → 2
```

## 8. Important Implementation Learnings

### A. Why do we need to propagate recursive return values?

Consider:

```python
if dfs(nei):
    return True
```

A cycle may be detected deep inside the recursion.

For example:

```text
dfs(1) → dfs(2) → dfs(3) → cycle detected
```

When `dfs(3)` returns `True`, `dfs(2)` must also return `True`, and then `dfs(1)` must propagate the result.

Simply calling `dfs(nei)` without checking its return value would discard the cycle detection result.

### B. Why shouldn't we return False when a neighbor has state 2?

Suppose the current node has three neighbors.

- First neighbor: fully explored (`state = 2`).
- Second neighbor: not visited (`state = 0`).
- Third neighbor: could lead to a cycle.

If we immediately return `False` when we encounter the first neighbor, we will never explore the remaining neighbors.

Therefore:

**A fully explored neighbor should be ignored, not treated as a reason to stop DFS.**

### C. When should a node become fully explored?

Only after all its neighbors have been processed successfully.

```python
state[node] = 2
return False
```

This happens at the end of the DFS function.

### D. Do we need an explicit current-path list?

No.

We could maintain a list or set representing the current DFS path, but the state array already tells us whether a node is in the recursion stack.

Therefore, the three-state approach is sufficient for detecting whether a cycle exists.

An explicit path can be useful if we want to reconstruct the actual cycle.

## 9. Complexity Analysis

Let `V` represent the number of vertices and `E` represent the number of directed edges.

| Operation | Complexity |
|---|---|
| Build adjacency list | `O(V + E)` |
| DFS traversal | `O(V + E)` |
| Total time | `O(V + E)` |
| Auxiliary space | `O(V)` |
| Total space including adjacency list | `O(V + E)` |

Each vertex transitions through the states at most once, and every directed edge is examined once.

Auxiliary space includes the state array and recursion stack. For very deep graphs, recursive DFS may hit Python's recursion-depth limit.

## 10. Edge Cases to Test

| Input | Expected result | Reason |
|---|---|---|
| `n = 0`, no edges | `False` | Empty graph |
| One vertex, no edges | `False` | Isolated vertex |
| `[(0, 1), (1, 2)]`, `n = 3` | `False` | Directed path |
| `[(0, 1), (1, 2), (2, 0)]`, `n = 3` | `True` | Directed cycle |
| `[(0, 0)]`, `n = 1` | `True` | Self-loop |
| `[(0, 1), (0, 2), (1, 3), (2, 3)]`, `n = 4` | `False` | Shared fully explored neighbor |
| `[(0, 1), (2, 3), (3, 2)]`, `n = 4` | `True` | Cycle in a disconnected component |
| No edges, `n = 4` | `False` | All vertices isolated |

## 11. BFS vs DFS for Directed Cycle Detection

There are two commonly used approaches:

| Property | DFS | BFS (Kahn's Algorithm) |
|---|---|---|
| Main idea | Detect a back edge to a node in the current recursion stack | Repeatedly remove nodes with indegree zero |
| Tracking | Three states | Indegree array and queue |
| Cycle indication | Encounter a neighbor with state `1` | Fewer than `V` nodes can be processed |
| Time | `O(V + E)` | `O(V + E)` |
| Space | `O(V)` auxiliary | `O(V)` auxiliary |

We have covered the DFS approach here. Kahn's algorithm is a separate approach based on topological sorting.

---

## 12. Pattern to Remember

**Directed cycle detection using DFS = Three states + back-edge detection.**

- `0`: Not visited.
- `1`: Currently exploring / in the recursion stack.
- `2`: Fully explored.

The most important condition:

```python
if state[nei] == 1:
    return True
```

A visited node alone does not indicate a cycle. It must be currently in the active DFS path.

For disconnected graphs, start DFS from every unvisited vertex.

## 14. My Reasoning Summary

When approaching cycle detection, first identify whether the graph is directed or undirected.

**For an undirected graph:**

A visited neighbor alone cannot indicate a cycle because the parent is also visited. We use parent tracking to distinguish the reverse edge from a genuine cycle.

**For a directed graph:**

Parent tracking is insufficient. We need to distinguish between a node that is currently being explored and one that has already been fully explored.

DFS naturally gives us this information through its recursion stack.

Therefore, we maintain three states:

- Not visited.
- Currently exploring.
- Fully explored.

If we encounter a neighbor that is currently being explored, we have found a back edge and therefore a directed cycle.

If the neighbor is fully explored, we ignore it and continue.

This is the reasoning behind three-state DFS for directed cycle detection.
