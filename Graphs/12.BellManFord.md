# Bellman-Ford Algorithm — Shortest Path with Negative Edge Weights

## 1. Objective

Given a weighted graph and a source vertex, find the shortest distance from the source to every other vertex.

Bellman-Ford supports:
- Positive edge weights
- Zero edge weights
- Negative edge weights
- Directed and undirected graphs
- Connected and disconnected graphs

It can also detect a **negative-weight cycle reachable from the source**.

Unlike Dijkstra, Bellman-Ford can handle negative edge weights.

---

## 2. Identify the Graph Properties

Before choosing an algorithm, understand the graph:

- **Weighted graph:** Edge weights are not necessarily equal.
- **Directed or undirected:** Both are supported. The edge representation must match the graph direction.
- **Disconnected graph:** Vertices unreachable from the source retain distance `inf`.
- **Cycles:** Ordinary cycles are allowed. Reachable negative-weight cycles can be detected.
- **Negative edges:** Supported.

### Which algorithm should we use?

| Algorithm | Edge weights | Purpose |
|---|---|---|
| BFS | All edges have equal weight | Single-source shortest path |
| 0-1 BFS | Only 0 or 1 | Single-source shortest path |
| Dijkstra | Non-negative weights | Single-source shortest path |
| Bellman-Ford | Positive, zero, negative | Single-source shortest path + negative-cycle detection |

---

## 3. Why Can't We Use Dijkstra?

Dijkstra uses a greedy approach.

It processes the vertex with the smallest tentative distance using a min-heap and considers that distance final.

This greedy guarantee depends on all edge weights being non-negative.

### Example

```text
S --2--> A --2--> B
 \              ^
  \-----5-------|
B --(-5)--> A
```

Edges:
- S → A = 2
- A → B = 2
- S → B = 5
- B → A = -5

Starting from S:

1. Initially, `dist[A] = 2` and `dist[B] = 5`.
2. Process A and improve `dist[B]` to 4.
3. Process B and improve `dist[A]` to -1.

A had already been processed at distance 2, but a later path improved it to -1.

This violates Dijkstra's greedy assumption.

**Important:** A negative edge does not necessarily imply an infinite loop. A negative-weight cycle is what makes shortest distances unbounded below.

---

## 4. Core Intuition Behind Bellman-Ford

Instead of finalizing a vertex when it is processed, Bellman-Ford repeatedly relaxes all edges.

### What is relaxation?

For an edge:

```text
u --wt--> v
```

Check whether reaching `v` through `u` gives a shorter distance.

Formula:

```python
newDistance = distance[u] + wt

if newDistance < distance[v]:
    distance[v] = newDistance
```

We repeat this process because a better distance to one vertex can lead to better distances for other vertices.

### Why V - 1 iterations?

A shortest path can be represented as a simple path when there are no negative-weight cycles.

A simple path does not visit the same vertex twice.

For a graph with V vertices:

```text
Maximum number of edges in a simple path = V - 1
```

For example, with 4 vertices:

```text
0 → 1 → 2 → 3
```

The path contains 3 edges.

Therefore, Bellman-Ford relaxes all edges V - 1 times.

**Guarantee:** After iteration `i`, shortest distances using at most `i` edges are accounted for.

This is a guarantee, not necessarily the exact number of iterations needed. Depending on edge ordering, improvements can propagate through multiple edges in a single iteration.

---

## 5. Algorithm

### Step 1: Initialize distances

Initialize every vertex's distance to infinity.

Set the source distance to zero.

```python
distance = [float('inf')] * V
distance[src] = 0
```

### Step 2: Relax all edges V - 1 times

For every iteration, traverse the complete edge list.

For each edge `(u, v, wt)`:

1. Check whether `u` is reachable from the source.
2. Calculate the new distance through `u`.
3. If the new distance is smaller, update `distance[v]`.

```python
for i in range(V - 1):
    for u, v, wt in edges:
        if distance[u] != float('inf'):
            newDistance = distance[u] + wt

            if newDistance < distance[v]:
                distance[v] = newDistance
```

We check `distance[u] != inf` because we cannot relax an edge from an unreachable vertex.

### Step 3: Detect a negative-weight cycle

After V - 1 iterations, traverse all edges one additional time.

If any edge can still be relaxed:

```python
distance[u] + wt < distance[v]
```

then a negative-weight cycle reachable from the source exists.

Why?

A shortest simple path can contain at most V - 1 edges. If a distance can still improve after V - 1 iterations, a reachable negative-weight cycle must be responsible.

An ordinary cycle does not cause this condition. Only a negative-weight cycle does.

---

## 6. Python Implementation

Assumption: The graph is directed and edges are represented as `(u, v, wt)`.

```python
def bellmanFord(V, edges, src):

    distance = [float('inf')] * V
    distance[src] = 0

    # Step 1: Relax all edges V-1 times
    for i in range(V - 1):

        for u, v, wt in edges:

            if distance[u] != float('inf'):

                newDistance = distance[u] + wt

                if newDistance < distance[v]:
                    distance[v] = newDistance

    # Step 2: Check for a reachable negative-weight cycle
    for u, v, wt in edges:

        if distance[u] != float('inf'):

            if distance[u] + wt < distance[v]:
                return "Negative cycle detected"

    return distance
```

**Why don't we construct an adjacency list?**

Bellman-Ford repeatedly iterates over every edge. The edge list itself is sufficient.

For an undirected graph, represent each undirected edge by both directed edges in the input list.

## 7. Dry Run

Consider:

```text
0 --4--> 1 --2--> 3
 \
  5
   \
    v
    2 --(-3)--> 1
```

Edges:

```python
edges = [
    (0, 1, 4),
    (0, 2, 5),
    (2, 1, -3),
    (1, 3, 2)
]
```

Source = 0

Number of vertices = 4

Maximum iterations = V - 1 = 3

### Initial distances

```text
[0, inf, inf, inf]
```

### Iteration 1

| Edge | Relaxation | Distance array |
|---|---|---|
| 0 → 1 (4) | dist[1] = 4 | [0, 4, inf, inf] |
| 0 → 2 (5) | dist[2] = 5 | [0, 4, 5, inf] |
| 2 → 1 (-3) | dist[1] = 2 | [0, 2, 5, inf] |
| 1 → 3 (2) | dist[3] = 4 | [0, 2, 5, 4] |

### Iteration 2

No edge gives a shorter distance.

```text
[0, 2, 5, 4]
```

### Iteration 3

No edge gives a shorter distance.

```text
[0, 2, 5, 4]
```

### Additional pass

No edge can be relaxed.

Therefore, no reachable negative-weight cycle exists.

**Final distances:**

```text
[0, 2, 5, 4]
```

### Important observation: Edge ordering

If the edges are ordered differently, the improved distances may take more iterations to propagate.

For example, if `(1, 3, 2)` appears before `(2, 1, -3)`, node 3 might not receive its improved distance until the next iteration.

This is why we cannot rely on one pass over the edges.

## 8. Negative-Weight Cycle Detection

Consider a reachable cycle:

```text
1 → 2  (weight 2)
2 → 3  (weight -5)
3 → 1  (weight 1)
```

Total cycle weight:

```text
2 + (-5) + 1 = -2
```

Every time we traverse this cycle, the total path cost decreases by 2.

Therefore, we can keep finding a lower path cost by going around the cycle again.

Bellman-Ford detects this because at least one edge remains relaxable in the additional pass.

### Reachable vs unreachable negative cycles

- **Reachable negative cycle:** Detected by the additional pass.
- **Unreachable negative cycle:** Not detected when running Bellman-Ford from a single source, because its vertices retain distance `inf`.

If we need to detect negative cycles anywhere in the graph, we can initialize all distances to zero (equivalent to adding a super-source connected to every vertex with a zero-weight edge).

---

## 9. Edge Cases

| Case | Expected behaviour |
|---|---|
| Disconnected graph | Unreachable vertices remain `inf` |
| Single vertex, source = that vertex | `[0]` |
| Single vertex, no edges | `[0]` |
| Negative edges, no negative cycle | Computes shortest distances |
| Reachable negative-weight cycle | Detects it |
| Unreachable negative-weight cycle | Not detected from the given source |
| Positive or zero-weight cycles | Works correctly |
| Empty edge list | Source distance 0, other vertices `inf` |

---

## 10. Complexity Analysis

Let:
- V = number of vertices
- E = number of edges

### Time Complexity

We relax all E edges for V - 1 iterations.

```text
(V - 1) × E
```

We also perform one additional pass over all E edges for negative-cycle detection.

Therefore:

```text
O((V - 1)E + E)
= O(VE)
```

**Time Complexity: O(VE)**

### Space Complexity

- Distance array: O(V)
- No additional adjacency list.
- Edge list is provided as input and is not counted as auxiliary space.

**Auxiliary Space: O(V)**

---

## 11. Optional Optimization — Early Stopping

If no edge is relaxed during an entire iteration, no further improvement is possible.

We can stop early.

```python
for i in range(V - 1):

    updated = False

    for u, v, wt in edges:

        if distance[u] != float('inf'):

            newDistance = distance[u] + wt

            if newDistance < distance[v]:
                distance[v] = newDistance
                updated = True

    if not updated:
        break
```

This can reduce runtime when distances converge early.

Worst-case time complexity remains O(VE).

---

## 12. Quick Recall

- **Objective:** Single-source shortest paths with negative edge weights.
- **Core technique:** Repeated relaxation of every edge.
- **Iterations:** V - 1.
- **Why V - 1?** A shortest simple path has at most V - 1 edges.
- **Negative cycle detection:** One additional pass.
- **Negative cycle detected?** At least one reachable edge can still be relaxed.
- **Disconnected graph:** Unreachable vertices remain `inf`.
- **Data structure:** Edge list; no heap or adjacency list required.
- **Time:** O(VE).
- **Auxiliary space:** O(V).
