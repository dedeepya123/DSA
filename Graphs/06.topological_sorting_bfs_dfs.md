# Topological Sorting — BFS (Kahn's Algorithm) and DFS

## 1. Objective

Given a directed graph, find a linear ordering of its vertices such that for every directed edge `u → v`, vertex `u` appears before vertex `v`.

A topological ordering is possible only if the graph is a **Directed Acyclic Graph (DAG)**.

Important properties:

- A DAG always has at least one valid topological ordering.
- A DAG can have multiple valid topological orderings.
- Every vertex must appear exactly once in the ordering.
- If the graph contains a directed cycle, no valid topological ordering exists.
- Disconnected DAGs can also have a valid topological ordering.

## 2. Thought Process

We know that a topological ordering is possible only when the directed graph has no cycles.

We can use either BFS or DFS to produce the ordering.

### Approach 1: BFS — Kahn's Algorithm

**Intuition: Process a vertex when all its incoming dependencies are resolved.**

For every directed edge `u → v`:

- `u` is a prerequisite of `v`.
- `v` has an incoming dependency from `u`.
- The indegree of `v` represents the number of its incoming dependencies.

Therefore:

1. Start with all vertices whose indegree is zero.
2. These vertices have no incoming dependencies and can be processed immediately.
3. Once a vertex is processed, its outgoing edges are conceptually removed.
4. Decrement the indegree of each outgoing neighbor.
5. If a neighbor's indegree becomes zero, all its incoming dependencies have been resolved. Add it to the queue.
6. Continue until the queue becomes empty.

**Cycle detection:**

If the number of processed vertices is less than `V`, the graph contains a cycle.

The vertices involved in a cycle cannot become eligible for processing because their incoming dependencies cannot all be resolved.

Some downstream vertices may also remain unprocessed.

### Kahn's Algorithm — Implementation

```python
from collections import defaultdict, deque

def topoSort(n, edges):
    adj = defaultdict(list)
    indegree = [0] * n

    # Build adjacency list and calculate indegree
    for u, v in edges:
        adj[u].append(v)
        indegree[v] += 1

    # Initialize queue with zero-indegree vertices
    queue = deque()

    for node in range(n):
        if indegree[node] == 0:
            queue.append(node)

    order = []

    while queue:
        curr = queue.popleft()
        order.append(curr)

        # Resolve dependencies of outgoing neighbors
        for nei in adj[curr]:
            indegree[nei] -= 1

            if indegree[nei] == 0:
                queue.append(nei)

    # If not all vertices are processed, a cycle exists
    if len(order) != n:
        raise ValueError("Cycle exists. Topological ordering is not possible.")

    return order
```

```python
edges = [(0, 1), (0, 2), (1, 3), (2, 3)]
```

```text
Queue = [0]
```

|---|---|---|---|


Every edge's source appears before its destination.

## 3. Approach 2: DFS — Finishing Order

**Intuition: Explore a node's outgoing neighbors completely before adding the node to the ordering.**

For a directed edge `u → v`:

- `u` must appear before `v` in the final ordering.
- During DFS, we explore `v` and its descendants before finishing `u`.
- Therefore, `v` gets appended to the ordering before `u`.
- Reversing the finishing order gives us the required topological ordering.

### Three DFS States

We use three states to distinguish unvisited, currently exploring, and fully explored vertices.

| State | Meaning |
|---|---|
| 0 | Not visited / not explored |
| 1 | Currently under exploration (in recursion stack) |
| 2 | Fully explored |

Why do we need three states?

- If a neighbor has state `0`, it has not been explored. Recursively visit it.
- If a neighbor has state `1`, it is already in the current DFS path. This is a back edge, which indicates a cycle.
- If a neighbor has state `2`, it is already fully explored. Continue with other neighbors.

### DFS Algorithm

1. Build the directed adjacency list.
2. Initialize all vertices with state `0`.
3. Iterate through every vertex to handle disconnected components.
4. For every unvisited vertex:
   - Mark it as state `1`.
   - Explore all its outgoing neighbors.
   - If a neighbor has state `1`, a cycle exists.
   - If a neighbor has state `0`, recursively apply DFS.
   - If a neighbor has state `2`, continue.
5. After all outgoing neighbors are explored:
   - Mark the current vertex as state `2`.
   - Append it to the ordering.
6. If a cycle is detected, no topological ordering exists.
7. Otherwise, reverse the finishing order.

### DFS — Implementation

```python
from collections import defaultdict

def topoSort(n, edges):
    adj = defaultdict(list)

    for u, v in edges:
        adj[u].append(v)

    # 0 = not visited
    # 1 = currently exploring
    # 2 = fully explored
    state = [0] * n
    order = []

    def dfs(node):
        state[node] = 1

        for nei in adj[node]:

            # Back edge: cycle detected
            if state[nei] == 1:
                return False

            # Explore an unvisited neighbor
            if state[nei] == 0:
                if not dfs(nei):
                    return False

            # State 2: already fully explored, continue

        # All outgoing neighbors are explored
        state[node] = 2
        order.append(node)

        return True

    # Handle disconnected components
    for node in range(n):
        if state[node] == 0:
            if not dfs(node):
                raise ValueError(
                    "Cycle exists. Topological ordering is not possible."
                )

    return order[::-1]
```

### DFS — Dry Run

Consider:

```text
    0
   / \
  1   2
   \ /
    3
```

Edges:

```python
edges = [(0, 1), (0, 2), (1, 3), (2, 3)]
```

Assume adjacency lists preserve the order in which edges are inserted.

DFS starts at `0` and explores `1` before `2`.

Traversal:

1. Visit `0` → state `1`.
2. Visit `1` → state `1`.
3. Visit `3` → state `1`.
4. Node `3` has no outgoing neighbors. Mark it state `2` and append `3`.
5. Finish `1`. Mark it state `2` and append `1`.
6. Return to `0` and visit `2`.
7. Node `2` has neighbor `3`, which is already fully explored (state `2`). Continue.
8. Finish `2` and append it.
9. Finish `0` and append it.

Finishing order:

```text
[3, 1, 2, 0]
```

Reverse the order:

```text
[0, 2, 1, 3]
```

This is a valid topological ordering.

## 4. Why Can There Be Multiple Valid Topological Orderings?

Consider:

```text
    0
   / \
  1   2
   \ /
    3
```

The constraints are:

- `0` must appear before `1`.
- `0` must appear before `2`.
- `1` must appear before `3`.
- `2` must appear before `3`.

There is no dependency between `1` and `2`.

Therefore, both are valid:

```text
[0, 1, 2, 3]
[0, 2, 1, 3]
```

**Key takeaway:**

Topological sorting defines dependency constraints, not one fixed ordering.

- Kahn's algorithm chooses from the available zero-indegree vertices.
- DFS follows a path deeply and uses finishing order.

The traversal strategy and neighbor-processing order can produce different valid results.

## 5. BFS vs DFS — Comparison

| Aspect | BFS — Kahn's Algorithm | DFS |
|---|---|---|
| Main idea | Process vertices with indegree zero | Append vertices after exploring outgoing neighbors |
| Data structure | Queue | Recursion stack |
| Additional tracking | Indegree array | Three-state array |
| Cycle detection | Processed count < V | Edge to state 1 |
| Ordering construction | Append when dequeued | Append when fully explored |
| Final reversal | Not required | Required |
| Disconnected graph | All zero-indegree vertices are initialized | Outer loop over all vertices |

Both approaches take O(V + E) time.

---

## 6. Edge Cases

1. **Empty graph (`n = 0`)**
   - Return an empty ordering.

2. **Single isolated vertex**
   - Valid ordering: `[0]`.

3. **Disconnected DAG**
   - Include every vertex from every component.
   - Kahn's algorithm initializes all zero-indegree vertices.
   - DFS must iterate over all vertices.

4. **Directed cycle**
   - No topological ordering exists.
   - Kahn's algorithm processes fewer than `V` vertices.
   - DFS detects a back edge to a state-1 vertex.

5. **Self-loop (`u → u`)**
   - A cycle exists; no topological ordering is possible.

6. **Multiple valid orderings**
   - Any ordering satisfying all directed-edge constraints is acceptable.

7. **Undirected graph**
   - This algorithm assumes a directed graph. Topological sorting is not defined for general undirected graphs.

## 7. Complexity Analysis

Let:
- `V` = number of vertices
- `E` = number of directed edges

### Kahn's BFS

**Time Complexity: O(V + E)**

- Building adjacency list and indegree: O(V + E).
- Initializing queue: O(V).
- Every vertex is processed once: O(V).
- Every edge is examined once: O(E).

**Auxiliary Space: O(V)**

- Indegree array: O(V).
- Queue: O(V).

### DFS

**Time Complexity: O(V + E)**

- Building adjacency list: O(V + E).
- Each vertex is explored once: O(V).
- Each edge is examined once: O(E).

**Auxiliary Space: O(V)**

- State array: O(V).
- Recursion stack: O(V).
- Ordering array: O(V).

**Total space for both:** O(V + E), including the adjacency list.

Note: Recursive DFS can hit Python's recursion-depth limit on very deep graphs. An iterative implementation can be used when necessary.

## 8. Quick Recall

### Kahn's BFS
- Directed graph → calculate indegrees.
- Indegree zero → ready to process.
- Process node → decrement indegree of outgoing neighbors.
- Indegree becomes zero → enqueue.
- Append processed vertices to order.
- If `len(order) < V` → cycle exists.

### DFS
- Use three states: `0`, `1`, `2`.
- State `1` → currently in recursion stack.
- Edge to state `1` → cycle.
- State `2` → already fully explored.
- Append node only after all outgoing neighbors are explored.
- Reverse finishing order.
