# Shortest Path in an Unweighted Graph using BFS

## 1. Objective

Given a graph and a source vertex `src`, find the shortest distance from the source to every other vertex.

For an unweighted graph, every edge contributes an equal cost of `1`.

The shortest path is the path containing the minimum number of edges.

## 2. Identify Graph Properties

Before choosing an algorithm, identify the graph properties:

- **Directed or Undirected:** Determines how we construct the adjacency list.
- **Connected or Disconnected:** Determines which vertices are reachable from the source.
- **Cyclic or Acyclic:** BFS can handle both using a visited mechanism.
- **Weighted or Unweighted:** Determines which shortest-path algorithm to use.

For this problem, we assume an unweighted graph. It can be either directed or undirected.

## 3. Thought Process — Why BFS?

We need to find the shortest distance from a source to every other vertex.

We can traverse a graph using BFS or DFS, but why choose BFS?

### Can we use DFS?

DFS explores deeply along one path before backtracking.

It does not explore vertices in increasing order of their distance from the source.

Therefore, the first path discovered to a vertex is not necessarily its shortest path.

### Can we use BFS?

Yes!

BFS explores vertices level by level, in increasing order of the number of edges from the source.

| BFS Level | Distance from source | Meaning |
|---|---:|---|
| Level 0 | 0 | Source vertex |
| Level 1 | 1 | Direct neighbors of source |
| Level 2 | 2 | Vertices reachable using 2 edges |
| Level 3 | 3 | Vertices reachable using 3 edges |

### Why is the first discovery final?

BFS processes vertices in non-decreasing order of their distance from the source.

When we first discover a neighbor `nei` from `curr`:

```python
distance[nei] = distance[curr] + 1
```

We have reached `nei` using the minimum possible number of edges.

Any later path reaching the same vertex would come from a vertex at the same or a greater BFS level. It cannot provide a shorter path.

Therefore:

**The first time a vertex is discovered, its shortest distance is finalized. We do not need to update it again.**

This property holds because every edge has equal weight (1).

## 4. Algorithm

1. Build the adjacency list.
   - For a directed graph, add `v` to `adj[u]`.
   - For an undirected graph, add both `v` to `adj[u]` and `u` to `adj[v]`.

2. Initialize the distance array:
   - Set the distance of every vertex to infinity.
   - Set `distance[src] = 0`.

3. Initialize the queue:
   - Add the source vertex to the queue.

4. Process the queue:
   - While the queue is not empty:
     - Remove the front vertex `curr`.
     - For every neighbor `nei`:
       - If `distance[nei]` is infinity:
         - Set `distance[nei] = distance[curr] + 1`.
         - Add `nei` to the queue.

5. Return the distance array.

Unreachable vertices retain their distance as infinity.

## 5. Python Implementation

```python
from collections import defaultdict, deque

def shortestDist(n, src, edges, directed=False):

    # Build adjacency list
    adj = defaultdict(list)

    for u, v in edges:
        adj[u].append(v)

        if not directed:
            adj[v].append(u)

    # Initialize distance array
    distance = [float('inf')] * n
    distance[src] = 0

    # Initialize BFS queue
    queue = deque([src])

    while queue:
        curr = queue.popleft()

        for nei in adj[curr]:

            # Discover only unvisited vertices
            if distance[nei] == float('inf'):

                distance[nei] = distance[curr] + 1
                queue.append(nei)

    return distance
```

The distance array itself acts as the visited mechanism:

- `inf` → not yet discovered.
- Finite distance → already discovered.

We do not need a separate visited set.

## 6. Dry Run

Consider the following undirected graph:

```text
       1 ─── 3
      /     /
     0 ─── 2
      \
       4 ─── 5
```

Edges:

```python
edges = [
    (0, 1),
    (0, 2),
    (1, 3),
    (2, 3),
    (0, 4),
    (4, 5)
]

n = 6
src = 0
```

### Initial state

```text
distance = [0, inf, inf, inf, inf, inf]
queue = [0]
```

### Processing

| Processed vertex | Newly discovered vertices | Queue | Distance array |
|---|---|---|---|
| 0 | 1, 2, 4 | [1, 2, 4] | [0, 1, 1, inf, 1, inf] |
| 1 | 3 | [2, 4, 3] | [0, 1, 1, 2, 1, inf] |
| 2 | None (3 already discovered) | [4, 3] | [0, 1, 1, 2, 1, inf] |
| 4 | 5 | [3, 5] | [0, 1, 1, 2, 1, 2] |
| 3 | None | [5] | [0, 1, 1, 2, 1, 2] |
| 5 | None | [] | [0, 1, 1, 2, 1, 2] |

Final distances:

| Vertex | Shortest distance from 0 |
|---|---:|
| 0 | 0 |
| 1 | 1 |
| 2 | 1 |
| 3 | 2 |
| 4 | 1 |
| 5 | 2 |

Notice that vertex `3` can be reached through both `1` and `2`.

When it is first discovered through `1`, its distance becomes `2`. When BFS later explores `2`, it does not update the distance because `3` has already been discovered.

## 7. Edge Cases

1. **Empty graph (`n = 0`)**
   - Return an empty distance array if no source is supplied.
   - A source-based query is invalid because no valid source exists.

2. **Single vertex**
   - If the vertex is the source, its distance is `0`.

3. **Disconnected graph**
   - Run BFS only from the given source.
   - Unreachable vertices retain distance `inf`.
   - Do not start BFS from every unvisited vertex; that would solve a different traversal problem.

4. **Cyclic graph**
   - BFS handles cycles using the distance check.
   - A vertex is enqueued only on its first discovery.

5. **Directed graph**
   - Same BFS algorithm works.
   - Add only the directed edge `u → v` to the adjacency list.

6. **Undirected graph**
   - Add both directions to the adjacency list.

7. **Multiple shortest paths**
   - A vertex may have multiple paths with the same minimum number of edges.
   - Its shortest distance remains unchanged after first discovery.

8. **Source has no outgoing edges**
   - Source distance is `0`; all other vertices remain unreachable unless connected through directed paths (none in this case).

## 8. Complexity Analysis

Let:

- `V` = number of vertices
- `E` = number of edges

**Time Complexity: O(V + E)**

- Building the adjacency list: O(V + E).
- Each vertex is enqueued and processed at most once: O(V).
- Each edge is examined at most once in a directed graph, or twice in an undirected adjacency list: O(E).

**Auxiliary Space: O(V)**

- Distance array: O(V).
- BFS queue: O(V).

**Total Space: O(V + E)** including the adjacency list.

## 9. Important Distinction — When Does BFS Work for Shortest Paths?

BFS guarantees shortest paths when every edge has equal cost.

| Graph type | Suitable algorithm |
|---|---|
| Unweighted graph (all edges cost 1) | BFS |
| Binary edge weights (0 or 1) | 0-1 BFS |
| Non-negative weighted graph | Dijkstra |
| Negative edge weights | Bellman-Ford |
| All-pairs shortest paths | Floyd-Warshall |

If edge weights differ, minimizing the number of edges does not necessarily minimize the total path cost.

## 10. Quick Recall

- Unweighted graph → BFS.
- BFS explores in increasing order of the number of edges from the source.
- Initialize all distances to infinity.
- Source distance = 0.
- Discover a neighbor only if its distance is infinity.
- Update distance using `distance[curr] + 1`.
- Enqueue the newly discovered neighbor.
- First discovery gives the shortest distance.
- Unreachable vertices remain infinity.
- Directed and undirected graphs use the same BFS logic; adjacency construction differs.
