# Floyd-Warshall Algorithm — All-Pairs Shortest Paths

## 1. Objective

Given a weighted graph with `V` vertices, find the shortest distance between **every pair of vertices**.

Unlike Dijkstra and Bellman-Ford, which calculate shortest distances from a single source, Floyd-Warshall calculates shortest distances between all pairs.

It uses **Dynamic Programming**.

### Graph properties

- Works with directed and undirected graphs.
- Supports positive, zero, and negative edge weights.
- Works with cyclic and acyclic graphs.
- Does not produce well-defined shortest distances if a negative-weight cycle exists.

---

## 2. Thought Process

We need the shortest distance from every vertex `i` to every vertex `j`.

One possible approach is to run Dijkstra or Bellman-Ford from every vertex.

Can we solve the all-pairs problem using a single algorithm?

Consider the possibility of travelling from `i` to `j` through an intermediate vertex `k`.

There are two choices:

1. Travel from `i` to `j` without using `k` as an intermediate vertex.
2. Travel from `i` to `j` through `k`, using the paths `i → k` and `k → j`.

We take the minimum of these two possibilities.

This gives us the DP transition.

---

## 3. DP State

Define:

`dp[i][j][k]`

as the shortest distance from vertex `i` to vertex `j`, using only vertices from `0` to `k` as intermediate vertices.

At every step, we decide whether allowing vertex `k` as an intermediate vertex improves the shortest distance.

### Choices

**Choice 1: Do not use `k`**

Keep the previously calculated shortest distance:

`dp[i][j][k-1]`

**Choice 2: Use `k`**

Travel from `i` to `k`, then from `k` to `j`:

`dp[i][k][k-1] + dp[k][j][k-1]`

### DP Transition

`dp[i][j][k] = min(dp[i][j][k-1], dp[i][k][k-1] + dp[k][j][k-1])`

---

## 4. Space Optimization

We do not need to maintain a separate 3D DP table.

We can update the same 2D distance matrix in place.

`dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`

Here, `k` is the currently allowed intermediate vertex.

### Why is the loop order K → I → J?

- `k`: Select the intermediate vertex.
- `i`: Select the source vertex.
- `j`: Select the destination vertex.

For every intermediate vertex `k`, we consider every possible pair `(i, j)`.

**Important invariant:**

Before processing `k`, the distance matrix contains shortest distances using previously processed intermediate vertices.

After processing `k`, it contains shortest distances allowing vertices up to `k` as intermediate vertices.

Therefore, `k` must be the outermost loop.

---

## 5. Initialization

Create a `V × V` distance matrix.

There are three cases:

1. Distance from a vertex to itself = `0`.
2. Distance between vertices with a direct edge = edge weight.
3. Distance between vertices without a direct edge = infinity.

If multiple direct edges exist between the same pair of vertices, retain the minimum weight.

For an undirected graph, add the reverse edge as well.

---

## 6. Algorithm

1. Initialize the distance matrix with infinity.
2. Set every diagonal element to zero.
3. Populate the matrix using the given edges.
4. Iterate over every vertex `k` as an intermediate vertex.
5. For every source `i` and destination `j`, check whether travelling through `k` gives a shorter distance.
6. Update the distance matrix whenever a shorter path is found.
7. After all iterations, check for a negative-weight cycle.

---

## 7. Python Implementation

The following implementation supports both directed and undirected graphs.

```python
def floydWarshall(V, edges, isDirected=True):

    # Step 1: Initialize distance matrix
    dp = [[float('inf')] * V for _ in range(V)]

    # Step 2: Distance from a node to itself is zero
    for i in range(V):
        dp[i][i] = 0

    # Step 3: Populate direct edge weights
    for u, v, wt in edges:

        dp[u][v] = min(dp[u][v], wt)

        if not isDirected:
            dp[v][u] = min(dp[v][u], wt)

    # Step 4: Floyd-Warshall DP
    for k in range(V):

        for i in range(V):

            for j in range(V):

                # Avoid adding infinity values
                if dp[i][k] != float('inf') and dp[k][j] != float('inf'):

                    newDistance = dp[i][k] + dp[k][j]

                    if newDistance < dp[i][j]:
                        dp[i][j] = newDistance

    # Step 5: Negative cycle detection
    for i in range(V):

        if dp[i][i] < 0:
            return "Negative cycle detected"

    return dp
```

## 8. Dry Run

Consider the directed graph:

```python
V = 3

edges = [
    (0, 1, 2),
    (1, 2, 3),
    (0, 2, 8)
]
```

### Initial distance matrix

```text
       0    1    2

0      0    2    8
1     INF   0    3
2     INF  INF   0
```

### Iteration: k = 0

Allow vertex `0` as an intermediate vertex.

No shorter paths are found.

### Iteration: k = 1

Allow vertex `1` as an intermediate vertex.

For `i = 0`, `j = 2`:

```text
Current distance = dp[0][2] = 8

Distance through 1:
dp[0][1] + dp[1][2]
= 2 + 3
= 5
```

Since `5 < 8`, update:

```text
dp[0][2] = 5
```

### Iteration: k = 2

Allow vertex `2` as an intermediate vertex.

No further improvements are found.

### Final distance matrix

```text
       0    1    2

0      0    2    5
1     INF   0    3
2     INF  INF   0
```

The shortest path from `0` to `2` is now `0 → 1 → 2`, with total cost `5`.

## 9. Negative Cycle Detection

A negative-weight cycle is a cycle whose total edge weight is negative.

An ordinary cycle is not necessarily a negative cycle.

For example:

- Cycle weight `+5`: Not a negative cycle.
- Cycle weight `0`: Not a negative cycle.
- Cycle weight `-3`: Negative cycle.

### How does Floyd-Warshall detect it?

Initially:

`dp[i][i] = 0`

If a vertex can travel through a negative-weight cycle and return to itself, its diagonal distance becomes negative.

Therefore, after completing Floyd-Warshall:

```python
for i in range(V):
    if dp[i][i] < 0:
        return "Negative cycle detected"
```

**If even one diagonal entry is negative, a negative cycle exists.**

A negative cycle causes shortest distances to be unbounded below for pairs that can reach and leave that cycle.

## 10. Complexity Analysis

### Time Complexity

- Initialize distance matrix: `O(V²)`
- Populate direct edges: `O(E)`
- Three nested loops: `O(V³)`
- Negative cycle detection: `O(V)`

Overall:

`O(V³)`

### Space Complexity

The distance matrix stores `V × V` elements.

Overall auxiliary space:

`O(V²)`

---

## 11. Edge Cases

1. **Disconnected graph:** Unreachable pairs remain infinity.
2. **Isolated vertex:** Its diagonal remains zero; other distances remain infinity.
3. **Zero-weight edges:** Supported.
4. **Negative edges:** Supported if there is no negative-weight cycle.
5. **Negative cycle:** Detect by checking whether any diagonal entry is negative.
6. **Duplicate edges:** Retain the minimum direct edge weight.
7. **Self-loop:** A negative self-loop is detected through the diagonal check.
8. **Undirected negative edge:** Creates a negative two-edge cycle because the edge can be traversed in both directions.

---

## 12. Comparison With Other Shortest-Path Algorithms

| Algorithm | Problem | Edge weights |
|---|---|---|
| BFS | Single-source | Equal edge weights |
| 0-1 BFS | Single-source | Only 0 and 1 |
| Dijkstra | Single-source | Non-negative |
| Bellman-Ford | Single-source | Negative edges supported |
| Floyd-Warshall | All-pairs | Negative edges supported |

---

## 13. Quick Recall

- All-pairs shortest-path algorithm.
- Uses Dynamic Programming.
- State: shortest distance from `i` to `j` using allowed intermediate vertices.
- Transition: `min(dist[i][j], dist[i][k] + dist[k][j])`.
- Loop order: `k → i → j`.
- Negative cycle detection: any `dist[i][i] < 0`.
- Time: `O(V³)`.
- Space: `O(V²)`.
