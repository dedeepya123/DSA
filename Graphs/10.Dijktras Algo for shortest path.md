# Dijkstra's Algorithm — Shortest Path in a Weighted Graph

## 1. Objective

Given a weighted graph and a source vertex, find the shortest distance from the source to every other vertex.

We can also find the actual shortest path from the source to a particular destination.

**Graph properties:**
- Weighted graph.
- Edge weights must be non-negative.
- Works for directed and undirected graphs.
- Can handle connected and disconnected graphs.
- Can handle cycles.

**Key constraint:** Dijkstra's algorithm does not work correctly with negative edge weights.

---

## 2. Why can't we use BFS?

BFS finds shortest paths in an unweighted graph, or when all edges have equal weight.

Why?

BFS explores nodes level by level. The first time a node is discovered, we know it has been reached using the minimum number of edges.

In a weighted graph, however, fewer edges do not necessarily mean lower cost.

Consider:

```text
0 --10-- 1
|
2
|
2 --3--- 1
```

There are two possible paths from node 0 to node 1:

- `0 → 1`: cost = 10
- `0 → 2 → 1`: cost = 2 + 3 = 5

If we use ordinary BFS, node 1 may be discovered first with cost 10. But a cheaper path with cost 5 exists.

Therefore, **the first time we discover a node in a weighted graph, its distance is not necessarily optimal.**

We need an algorithm that can update a node's distance whenever a better path is discovered.

That leads us to Dijkstra's algorithm.

---

## 3. Core intuition

Imagine that we are at the source node.

From the source, we can reach multiple neighbouring nodes, each with a different cost.

Which node should we explore next?

We should explore the node that currently has the **smallest known distance from the source**.

Why?

Because all edge weights are non-negative. Once we extract the node with the smallest tentative distance, no path through another unprocessed node can produce a smaller distance for it.

This is the greedy idea behind Dijkstra's algorithm.

But how do we efficiently find the node with the smallest tentative distance?

**Use a Min-Heap (Priority Queue).**

The min-heap always gives us the entry with the smallest distance.

---

## 4. Important concepts

### A. Distance array

```python
distance = [float('inf')] * n
distance[src] = 0
```

The distance array stores the shortest distance currently known from the source to every vertex.

Initially:
- Source distance = 0.
- All other distances = infinity because we have not discovered a path to them yet.

Infinity also represents an unreachable vertex if its distance remains unchanged after the algorithm finishes.

### B. Min-Heap

```python
minHeap = [(0, src)]
```

Each heap entry is a pair:

```python
(distance, node)
```

For example:

```python
(5, 2)
```

means that we currently know a path from the source to node 2 with total cost 5.

The heap helps us efficiently select the node with the smallest tentative distance.

**Important:** A node can have multiple entries in the heap because we may discover better paths to it over time.

### C. Relaxation

Relaxation means checking whether we can reach a neighbour through the current node at a lower cost than its currently known distance.

Suppose we are processing node `curr` and considering its neighbour `nei`.

Calculate:

```python
newDistance = dist + wt
```

Where:
- `dist` = distance associated with the current heap entry.
- `wt` = weight of the edge from `curr` to `nei`.

Compare the new distance with the existing distance:

```python
if newDistance < distance[nei]:
    distance[nei] = newDistance
    heapq.heappush(minHeap, (newDistance, nei))
```

If the new route is cheaper, update the distance and push the improved entry into the heap.

This operation is called **relaxation**.

### D. Stale heap entries

Consider these edges:

```text
0 → 1 : 10
0 → 2 : 2
2 → 1 : 3
```

Initially, we discover node 1 with distance 10.

We push:

```python
(10, 1)
```

Later, we process node 2 and discover a better route to node 1:

```python
2 + 3 = 5
```

We update the distance and push:

```python
(5, 1)
```

Now both entries can exist in the heap:

```python
(5, 1)
(10, 1)
```

We process `(5, 1)` first.

When `(10, 1)` is eventually popped, it is outdated because the best known distance is already 5.

We skip it:

```python
if dist > distance[curr]:
    continue
```

We don't remove outdated entries immediately when a better path is found. We simply skip them when they are popped.

---

## 5. Algorithm

1. Build the adjacency list.
   - For an undirected graph, add both directions.
   - For a directed graph, add only the given direction.

2. Initialize the distance array with infinity.

3. Set the source distance to 0.

4. Initialize a min-heap with `(0, src)`.

5. While the heap is not empty:

   a. Pop the entry with the smallest distance.

   b. Check whether the entry is outdated. If its distance is greater than the current best distance, skip it.

   c. Explore every neighbour of the current node.

   d. Calculate the new distance:

   ```python
   newDistance = dist + wt
   ```

   e. If the new distance is smaller than the neighbour's current distance:
   - Update `distance[nei]`.
   - Push `(newDistance, nei)` into the heap.

6. Return the distance array.

---

## 6. Implementation — Shortest distances to every vertex

```python
from collections import defaultdict
import heapq

def dijkstra(n, edges, src):

    adj = defaultdict(list)

    # Build undirected adjacency list
    for u, v, wt in edges:
        adj[u].append((v, wt))
        adj[v].append((u, wt))

    # Initialize distances
    distance = [float('inf')] * n
    distance[src] = 0

    # (distance, node)
    minHeap = [(0, src)]

    while minHeap:

        dist, curr = heapq.heappop(minHeap)

        # Skip outdated heap entries
        if dist > distance[curr]:
            continue

        # Explore neighbours
        for nei, wt in adj[curr]:

            newDistance = dist + wt

            # Relaxation
            if newDistance < distance[nei]:

                distance[nei] = newDistance
                heapq.heappush(minHeap, (newDistance, nei))

    return distance
```

Example:

```python
n = 4

edges = [
    (0, 1, 10),
    (0, 2, 2),
    (2, 1, 3),
    (1, 3, 4),
    (2, 3, 10)
]

print(dijkstra(n, edges, 0))
```

Output:

```python
[0, 5, 2, 9]
```

The shortest distances from node 0 are:
- Node 0: 0
- Node 1: 5
- Node 2: 2
- Node 3: 9

## 7. Finding the actual shortest path

The distance array gives us the minimum cost, but it does not tell us which nodes form the path.

To reconstruct the path, maintain an additional array called `parent`.

```python
parent = [-1] * n
```

Whenever a relaxation succeeds:

```python
if newDistance < distance[nei]:

    distance[nei] = newDistance
    parent[nei] = curr

    heapq.heappush(minHeap, (newDistance, nei))
```

Why update the parent only when relaxation succeeds?

Because the parent must represent the predecessor on the currently best-known path.

If we find a better route to a node, its parent must also change.

### Path reconstruction

Once Dijkstra finishes, start from the destination and follow the parent pointers until reaching the source.

```python
path = []
node = dest

while node != -1:
    path.append(node)
    node = parent[node]

path.reverse()
```

We reverse the path because we traverse it backwards, from destination to source.

### Complete implementation

```python
from collections import defaultdict
import heapq

def dijkstra(n, edges, src, dest):

    adj = defaultdict(list)

    for u, v, wt in edges:
        adj[u].append((v, wt))
        adj[v].append((u, wt))

    distance = [float('inf')] * n
    parent = [-1] * n

    distance[src] = 0
    minHeap = [(0, src)]

    while minHeap:

        dist, curr = heapq.heappop(minHeap)

        if dist > distance[curr]:
            continue

        for nei, wt in adj[curr]:

            newDistance = dist + wt

            if newDistance < distance[nei]:

                distance[nei] = newDistance
                parent[nei] = curr

                heapq.heappush(
                    minHeap,
                    (newDistance, nei)
                )

    # Destination is unreachable
    if distance[dest] == float('inf'):
        return float('inf'), []

    # Reconstruct path
    path = []
    node = dest

    while node != -1:
        path.append(node)
        node = parent[node]

    path.reverse()

    return distance[dest], path
```

Example:

```python
n = 4

edges = [
    (0, 1, 10),
    (0, 2, 2),
    (2, 1, 3),
    (1, 3, 4),
    (2, 3, 10)
]

distance, path = dijkstra(n, edges, 0, 3)

print(distance)  # 9
print(path)      # [0, 2, 1, 3]
```

### Dry run: Parent updates

| Node | Parent update |
|---|---|
| 1 | Initially 0, later updated to 2 |
| 2 | 0 |
| 3 | 1 |

Final arrays:

```python
distance = [0, 5, 2, 9]
parent   = [-1, 2, 0, 1]
```

Reconstructing backwards:

```text
3 → 1 → 2 → 0
```

Reverse:

```text
0 → 2 → 1 → 3
```

Total path cost = 2 + 3 + 4 = 9.

## 8. Complexity analysis

Let:
- V = number of vertices.
- E = number of edges.

### A. Building the adjacency list

For an undirected graph, each edge is stored twice.

Time complexity:

`O(V + E)`

### B. Distance initialization

We initialize an array of size V.

Time complexity:

`O(V)`

### C. Heap operations

This is the important part.

- Every successful relaxation pushes one entry into the heap.
- Each adjacency entry is examined once when its current node is processed.
- There can be up to O(E) successful relaxations.
- Therefore, there can be up to O(E) heap pushes and O(E) heap pops.

A binary heap operation costs `O(log H)`, where H is the heap size.

Since the heap can contain up to O(E) entries:

`O(log E)` per operation.

Total heap-operation cost:

`O(E log E)`

### D. Overall time complexity

Combining the operations:

`O(V + E + E log E)`

For a simple graph, E is at most O(V²), so:

`log E = O(log V)`

Therefore, the commonly stated complexity is:

**O((V + E) log V)**

For a connected graph, this is often simplified to:

**O(E log V)**

### Space complexity

| Data structure | Space |
|---|---|
| Adjacency list | O(V + E) |
| Distance array | O(V) |
| Parent array (if reconstructing path) | O(V) |
| Min-heap (lazy entries) | O(E) |

Overall:

**O(V + E)**

## 9. Important edge cases

1. **Source and destination are the same**
   - Distance = 0.
   - Path = `[src]`.

2. **Destination is unreachable**
   - Distance remains infinity.
   - Return an empty path.

3. **Disconnected graph**
   - Dijkstra processes only vertices reachable from the source.
   - Unreachable vertices remain at infinity.

4. **Cycles**
   - Handled through relaxation and the distance array.
   - A node is updated only when a strictly shorter distance is found.

5. **Multiple routes to the same node**
   - A node can be pushed into the heap multiple times.
   - Outdated entries are skipped when popped.

6. **Zero-weight edges**
   - Allowed.
   - Dijkstra still works.

7. **Negative-weight edges**
   - Not allowed.
   - Dijkstra's greedy property no longer holds.

8. **Multiple shortest paths with equal cost**
   - The strict `<` comparison keeps the first discovered optimal parent.
   - The algorithm returns one shortest path, not necessarily all shortest paths.

---

## 10. Dijkstra vs other shortest-path algorithms

| Algorithm | Edge weights | Main data structure / idea |
|---|---|---|
| BFS | All equal (typically 1) | Queue |
| Multi-Source BFS | All equal (typically 1) | Queue initialized with all sources |
| 0-1 BFS | Only 0 or 1 | Deque |
| Dijkstra | Non-negative weights | Min-heap |
| Bellman-Ford | Can include negative weights | Repeated edge relaxation |
| Floyd-Warshall | Can include negative weights, but no negative cycles for finite shortest paths | Dynamic programming |
| DAG shortest path | Positive or negative | Topological ordering + relaxation |

---

## 11. Quick recall

When you see a shortest-path problem, ask:

1. Are all edge weights equal? → BFS.
2. Are weights only 0 and 1? → 0-1 BFS.
3. Are weights arbitrary but non-negative? → Dijkstra.
4. Are negative weights possible? → Bellman-Ford (or DAG shortest path if the graph is a DAG).
5. Do we need shortest distances between every pair of vertices? → Floyd-Warshall may be appropriate.

**Dijkstra in one sentence:**

Always process the reachable node with the smallest tentative distance, relax its outgoing edges, and use a min-heap to efficiently select the next node.
