# Multi-Source Dijkstra — Shortest Distance from Any Source

## 1. Objective

Given a weighted graph and a list of source vertices, find the shortest distance from **any one of the sources** to every other vertex.

For every vertex `v`, we want:

\[
dist[v] = \min_{s \in Sources} shortestDistance(s,v)
\]

In other words, find the minimum distance from the set of sources to each vertex.

### Graph properties

- Weighted graph.
- Edge weights must be non-negative.
- Can be directed or undirected.
- Can contain cycles.
- Can be connected or disconnected.

---

## 2. Core intuition

Recall ordinary Dijkstra's algorithm.

In ordinary Dijkstra:
- We start from one source.
- Set its distance to 0.
- Insert it into the min-heap.
- Explore the graph by always processing the node with the smallest tentative distance.
- Relax its neighbours.

Now imagine we have multiple sources.

Instead of starting from one source, we start from all sources simultaneously.

Every source has distance 0 from itself.

We initialize all sources with distance 0 and insert all of them into the min-heap before starting the algorithm.

The rest of the algorithm remains exactly the same as ordinary Dijkstra.

**Key idea:** All sources compete to provide the shortest distance to every vertex.

---

## 3. Why process all sources together?

Suppose we have two sources: `0` and `4`.

A particular node might be:
- Distance 8 from source 0.
- Distance 3 from source 4.

We want the minimum distance, which is 3.

If we run Dijkstra independently from every source, we would need to calculate each result separately and then take the minimum distance for every vertex.

Instead, Multi-Source Dijkstra performs this in one run using a shared distance array and a shared min-heap.

This allows the algorithm to find the minimum distance from any source.

---

## 4. Difference from ordinary Dijkstra

### Ordinary Dijkstra

Initialize one source:

```python
distance = [float('inf')] * n
distance[src] = 0

minHeap = [(0, src)]
```

### Multi-Source Dijkstra

Initialize all sources:

```python
distance = [float('inf')] * n
minHeap = []

for src in sources:
    distance[src] = 0
    heapq.heappush(minHeap, (0, src))
```

Everything after initialization remains the same.

---

## 5. Algorithm

1. Build the adjacency list.
   - For an undirected graph, add both directions.
   - For a directed graph, add only the given direction.

2. Initialize the distance array with infinity.

3. Initialize an empty min-heap.

4. For every source:
   - Set its distance to 0.
   - Push `(0, source)` into the min-heap.
   - Check for duplicates so that each source is initialized only once.

5. While the heap is not empty:

   a. Pop the entry with the smallest distance.

   b. Skip outdated entries.

   c. Explore every neighbour of the current node.

   d. Calculate:

   ```python
   newDistance = dist + wt
   ```

   e. If the new distance is smaller than the neighbour's current distance:
   - Update the distance.
   - Push the improved entry into the heap.

6. Return the distance array.

---

## 6. Implementation

```python
from collections import defaultdict
import heapq

def multiSourceDijkstra(n, edges, sources):

    adj = defaultdict(list)

    # Build undirected adjacency list
    for u, v, wt in edges:
        adj[u].append((v, wt))
        adj[v].append((u, wt))

    distance = [float('inf')] * n
    minHeap = []

    # Initialize all sources
    for src in sources:

        # Avoid duplicate source entries
        if distance[src] == float('inf'):
            distance[src] = 0
            heapq.heappush(minHeap, (0, src))

    # Dijkstra's algorithm
    while minHeap:

        dist, curr = heapq.heappop(minHeap)

        # Skip outdated entries
        if dist > distance[curr]:
            continue

        for nei, wt in adj[curr]:

            newDistance = dist + wt

            # Relaxation
            if newDistance < distance[nei]:

                distance[nei] = newDistance

                heapq.heappush(
                    minHeap,
                    (newDistance, nei)
                )

    return distance
```

## 7. Dry run

Consider the following undirected weighted graph:

```text
0 --4-- 1 --2-- 2 --3-- 3
```

Let the sources be:

```python
sources = [0, 3]
```

We want the minimum distance from either source to every vertex.

### Initialization

```python
distance = [0, inf, inf, 0]
minHeap = [(0, 0), (0, 3)]
```

Both sources start at distance zero.

### Processing

- Process node 0: relax node 1 with distance 4.
- Process node 3: relax node 2 with distance 3.
- Process node 2: improve node 1 to distance 5? No, its current distance is 4, so no update.
- Process node 1: no better distances are found.

### Final result

```python
distance = [0, 4, 3, 0]
```

| Node | Distance from source 0 | Distance from source 3 | Final minimum |
|---|---:|---:|---:|
| 0 | 0 | 9 | 0 |
| 1 | 4 | 5 | 4 |
| 2 | 6 | 3 | 3 |
| 3 | 9 | 0 | 0 |

The algorithm returns the minimum distance from any source.

## 8. Complexity analysis

Let:
- V = number of vertices.
- E = number of edges.
- K = number of sources.

### Adjacency list construction

For an undirected graph, each edge is stored twice.

Time: `O(V + E)`

### Source initialization

We iterate through K sources and insert each unique source into the heap.

Time: `O(K log K)` as a conservative heap insertion bound.

### Heap operations and relaxation

- Every adjacency entry is examined at most once when its node is processed with its current best distance.
- There can be up to O(E) successful relaxations.
- Each successful relaxation causes one heap push.
- There can be up to O(E) heap pushes and pops.
- Each heap operation costs O(log E), since the lazy-entry heap can contain O(E) entries.

Time: `O(E log E)`

### Overall time complexity

\[
O(V+E+K\log K+E\log E)
\]

Since K ≤ V, and for a simple graph `log E = O(log V)`, the commonly stated bound is:

\[
\boxed{O((V+E)\log V)}
\]

### Space complexity

| Data structure | Space |
|---|---|
| Adjacency list | O(V + E) |
| Distance array | O(V) |
| Min-heap | O(E) |

Overall:

\[
\boxed{O(V+E)}
\]

## 9. Important edge cases

1. **Duplicate sources**
   - Initialize each source only once.
   - The distance check prevents duplicate heap insertion.

2. **Empty source list**
   - No nodes are processed.
   - All distances remain infinity.

3. **Disconnected graph**
   - Nodes unreachable from every source remain at infinity.

4. **A node is itself a source**
   - Its distance is always 0.

5. **Zero-weight edges**
   - Allowed. Dijkstra still works.

6. **Multiple sources reach the same node**
   - The algorithm keeps the minimum distance among all sources.

7. **Negative edge weights**
   - Not supported. Dijkstra requires non-negative weights.

8. **Duplicate shortest paths**
   - The distance array stores the minimum cost, regardless of how many paths achieve it.

## 10. Multi-Source BFS vs Multi-Source Dijkstra

| Property | Multi-Source BFS | Multi-Source Dijkstra |
|---|---|---|
| Graph | Unweighted / equal weights | Weighted |
| Edge weights | Equal (typically 1) | Arbitrary non-negative |
| Data structure | Queue | Min-heap |
| Initialization | All sources in queue | All sources in min-heap |
| Update condition | First discovery | Relaxation |
| Complexity | O(V + E) | O((V + E) log V) |

The important difference is that BFS can finalize a node on its first discovery because all edge weights are equal.

Dijkstra must use relaxation because a cheaper route may be discovered later.

---

## 11. Quick recall

When a shortest-path problem gives multiple starting points:

1. Are all edge weights equal? → Multi-Source BFS.
2. Are weights only 0 or 1? → Multi-Source 0-1 BFS.
3. Are weights arbitrary but non-negative? → Multi-Source Dijkstra.
4. Can weights be negative? → Consider Bellman-Ford or a suitable DAG shortest-path algorithm.

**Multi-Source Dijkstra in one sentence:**

Initialize all sources with distance zero in a shared min-heap, then perform ordinary Dijkstra relaxation to find the minimum distance from any source to every vertex.
