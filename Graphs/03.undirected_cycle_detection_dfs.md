# Undirected Cycle Detection Using DFS

## 1. Objective

Given an undirected graph with `n` vertices and an edge list, determine whether the graph contains a cycle.

- Return `True` if a cycle exists.
- Return `False` otherwise.

## 2. Understand the graph

Before choosing the algorithm, identify:

- **Graph type:** Undirected.
- **Connectivity:** The graph may be connected or disconnected.
- **Representation:** Convert the edge list into an adjacency list.
- **Vertices:** Assume vertices are numbered from `0` to `n - 1`, including isolated vertices.

For every undirected edge `(u, v)`, add both directions:

```python
adjlist[u].append(v)
adjlist[v].append(u)
```

## 3. Core intuition

DFS explores a path as deeply as possible before backtracking.

In an undirected graph, when we traverse an edge from a parent to a child, the child can see the parent as a visited neighbor. This is normal and does not indicate a cycle.

Therefore, we need to track the **parent** of every node.

For the current node:

1. If a neighbor is unvisited, recursively explore it.
2. If a neighbor is visited and is the parent, ignore it.
3. If a neighbor is visited and is not the parent, a cycle exists.

The key condition is:

```python
elif nei != parent:
    return True
```

This approach assumes a simple undirected graph without parallel edges. If parallel edges are allowed, parent-edge tracking is needed.

## 4. Algorithm

### Step 1: Build the adjacency list

Store each undirected edge in both directions.

### Step 2: Initialize `visited`

Use a shared `visited` set across all DFS calls and connected components.

### Step 3: Implement recursive DFS

For `dfs(node, visited, parent)`:

1. Mark `node` as visited.
2. Iterate over its neighbors.
3. If a neighbor is unvisited:
   - Recursively call `dfs(nei, visited, node)`.
   - If the recursive call returns `True`, immediately return `True` from the current call.
4. Otherwise, if the neighbor is visited and is not the parent, return `True`.
5. If all neighbors have been explored without detecting a cycle, return `False`.

### Step 4: Handle disconnected graphs

Iterate over every vertex from `0` to `n - 1`.

Whenever a vertex is unvisited, start DFS from it with parent `-1`. If any DFS call detects a cycle, return `True`.

If all components are explored without finding a cycle, return `False`.

## 5. Implementation

```python
from collections import defaultdict


def hasCycle(n, edges):
    adjlist = defaultdict(list)

    # Build the undirected adjacency list.
    for u, v in edges:
        adjlist[u].append(v)
        adjlist[v].append(u)

    def dfs(node, visited, parent):
        visited.add(node)

        for nei in adjlist[node]:
            if nei not in visited:
                # Propagate cycle detection up the recursion stack.
                if dfs(nei, visited, node):
                    return True

            elif nei != parent:
                return True

        return False

    visited = set()

    # Check every connected component.
    for node in range(n):
        if node not in visited:
            if dfs(node, visited, -1):
                return True

    return False
```

## 6. Important lesson: Propagating recursive return values

A recursive function can detect a cycle deep in the graph, but every caller must preserve that result.

Consider this triangle:

```text
    0
   / \
  1---2
```

Edges: `[(0, 1), (1, 2), (2, 0)]`

The recursive calls go from `0` to `1`, then from `1` to `2`.

At node `2`, neighbor `0` is already visited and is not the parent. Therefore, `dfs(2)` returns `True`.

What happens next?

- `dfs(1)` receives `True` from `dfs(2)` and must return `True` immediately.
- `dfs(0)` receives `True` from `dfs(1)` and must also return `True`.
- The outer function receives `True` and reports that the graph contains a cycle.

**Incorrect pattern:**

```python
dfs(nei, visited, node)
```

This calls the function but discards its return value. A cycle detected deeper in the recursion may therefore be lost.

**Correct pattern:**

```python
if dfs(nei, visited, node):
    return True
```

This propagates the result through every active recursive call.

Also, do not return `False` just because one neighbor is the parent. Continue exploring the remaining neighbors. Return `False` only after all neighbors have been checked and no cycle was found.

## 7. Dry run: A graph without a cycle

Consider the path:

```text
0 ---- 1 ---- 2
```

Edges: `[(0, 1), (1, 2)]`

1. `dfs(0, -1)` visits `0`.
2. It calls `dfs(1, 0)`.
3. Node `1` ignores `0`, its parent, and calls `dfs(2, 1)`.
4. Node `2` ignores `1`, its parent. It has no other neighbors, so it returns `False`.
5. Node `1` finishes checking its neighbors and returns `False`.
6. Node `0` finishes checking its neighbors and returns `False`.

No cycle is detected.

## 8. Complexity analysis

Let `V` be the number of vertices and `E` the number of edges.

- Building the adjacency list: `O(V + E)`, including vertex initialization/representation.
- DFS over all components: `O(V + E)`.
- **Total time complexity:** `O(V + E)`.
- **Auxiliary space:** `O(V)` for `visited` and the recursion stack in the worst case.
- **Total space including adjacency list:** `O(V + E)`.

For very deep graphs, recursive DFS may hit Python's recursion-depth limit; iterative DFS is an alternative.

## 9. Edge cases

| Case | Expected result |
|---|---|
| `n = 0`, no edges | `False` |
| One isolated vertex | `False` |
| A simple path | `False` |
| A triangle | `True` |
| A four-vertex cycle | `True` |
| Multiple disconnected components, none containing a cycle | `False` |
| One component contains a cycle, others do not | `True` |
| All vertices are isolated | `False` |

## 10. BFS vs. DFS for undirected cycle detection

| Property | BFS | DFS |
|---|---|---|
| Traversal mechanism | Queue | Recursion or explicit stack |
| Parent tracking | Required | Required |
| Cycle condition | Visited neighbor is not the parent | Visited neighbor is not the parent |
| Disconnected graph | Start from every unvisited vertex | Start from every unvisited vertex |
| Time complexity | `O(V + E)` | `O(V + E)` |
| Main implementation concern | Enqueue and mark visited correctly | Propagate recursive return values |

## 11. Pattern to remember

**Undirected cycle detection = BFS/DFS + parent tracking.**

For DFS, remember three things:

1. Track the parent to ignore the reverse traversal of an undirected edge.
2. Return `True` when a visited, non-parent neighbor is found.
3. Propagate `True` from recursive calls using `if dfs(...): return True`.

For disconnected graphs, run the traversal from every unvisited vertex.
