# Multi-Source BFS — Shortest Distance from Any Source

## 1. Objective

Given a graph containing multiple source vertices, find the shortest distance from **any source vertex to every other vertex**.

For an unweighted graph, every edge has an equal cost of 1.

For every vertex `v`, we want:

\[
dist[v] = \min_{s \in Sources} dist(s,v)
\]

In other words, find the minimum number of edges required to reach each vertex from the nearest source.

## 2. Thought Process — Why Multi-Source BFS?

In ordinary single-source BFS, we start from one source and explore the graph level by level.

Now suppose a graph has multiple sources.

We need to find the shortest distance from any of these sources to every vertex.

### Why not run BFS separately from each source?

Consider two sources, `src1` and `src2`.

A vertex might be:
- 5 edges away from `src1`.
- 2 edges away from `src2`.

If we want the minimum distance from any source, the answer for that vertex is 2.

Running BFS independently from each source would calculate both distances separately and require additional work to compare them.

Instead, we can start BFS from all sources simultaneously.

### Why enqueue all sources at the beginning?

Think of multiple fires starting at different locations at the same time and spreading across the graph.

- Every source starts at distance 0.
- Their immediate neighbors are at distance 1.
- The next layer of vertices is at distance 2.
- The process continues level by level.

Because BFS explores vertices in non-decreasing order of distance, the first time a vertex is discovered, we have found its minimum distance from any source.

This is the same first-discovery property we used in single-source BFS.

**Important:** This guarantee holds because every edge has equal weight (1).

## 3. Algorithm

1. Build the adjacency list.
   - Directed graph: add `v` to `adj[u]`.
   - Undirected graph: add both directions.

2. Initialize the distance array:
   - Set every vertex distance to infinity.

3. Initialize the queue:
   - Iterate through all source vertices.
   - Set each source distance to 0.
   - Enqueue each source.
   - Avoid adding duplicate sources.

4. Perform BFS:
   - While the queue is not empty:
     - Dequeue the current vertex.
     - Explore all its neighbors.
     - If a neighbor's distance is infinity:
       - Set its distance to `distance[curr] + 1`.
       - Enqueue that neighbor.

5. Return the distance array.

Vertices unreachable from every source retain infinity.

## 4. Python Implementation

```python
from collections import defaultdict, deque

def MultiSourceBFS(n, edges, sources, isDirected=False):

    # Build adjacency list
    adj = defaultdict(list)

    for u, v in edges:
        adj[u].append(v)

        if not isDirected:
            adj[v].append(u)

    # Initialize distances
    distance = [float('inf')] * n

    # Initialize queue with all sources
    queue = deque()

    for src in sources:
        if distance[src] == float('inf'):
            distance[src] = 0
            queue.append(src)

    # Multi-source BFS
    while queue:
        curr = queue.popleft()

        for nei in adj[curr]:

            if distance[nei] == float('inf'):
                distance[nei] = distance[curr] + 1
                queue.append(nei)

    return distance
```

## 5. Dry Run

Consider the following undirected graph:

```text
0 — 1 — 2 — 3 — 4
S               S
```

Input:

```python
n = 5
edges = [
    (0, 1),
    (1, 2),
    (2, 3),
    (3, 4)
]

sources = [0, 4]
```

### Initial state

Both sources have distance 0.

```text
distance = [0, inf, inf, inf, 0]
queue = [0, 4]
```

### BFS execution

| Processed vertex | Newly discovered vertices | Queue | Distance array |
|---|---|---|---|
| 0 | 1 | [4, 1] | [0, 1, inf, inf, 0] |
| 4 | 3 | [1, 3] | [0, 1, inf, 1, 0] |
| 1 | 2 | [3, 2] | [0, 1, 2, 1, 0] |
| 3 | None (2 already discovered) | [2] | [0, 1, 2, 1, 0] |
| 2 | None | [] | [0, 1, 2, 1, 0] |

Final output:

```python
[0, 1, 2, 1, 0]
```

Vertex 2 is at distance 2 from both sources.

The algorithm does not need to calculate both distances separately. The simultaneous BFS expansion discovers the vertex at its minimum distance.

## 6. Complexity Analysis

Let:
- `V` = number of vertices.
- `E` = number of edges.

### Time Complexity: O(V + E)

Break it down:

1. Building the adjacency list takes O(V + E).
2. Each vertex is enqueued at most once because we enqueue it only when its distance is infinity.
3. Each vertex is dequeued at most once.
4. Across all vertices, we examine every adjacency entry at most once.

Therefore:

\[
O(V) + O(E) = O(V+E)
\]

**Interview explanation:**

Every vertex is processed at most once, and all adjacency entries are examined at most once. Therefore, BFS takes O(V + E) time.

### Space Complexity

| Data structure | Space |
|---|---:|
| Adjacency list | O(V + E) |
| Distance array | O(V) |
| Queue | O(V) |

- Auxiliary space excluding the graph: O(V).
- Total space including adjacency list: O(V + E).

## 7. Edge Cases

1. **Empty graph**
   - If `n = 0` and there are no sources, return an empty distance array.

2. **Arbitrary number of sources**
   - Accept a list of sources instead of fixed arguments such as `src1` and `src2`.
   - The same implementation supports any number of sources.

3. **Single source**
   - Works exactly like ordinary single-source BFS.

4. **No sources**
   - All distances remain infinity.

5. **Duplicate sources**
   - Add each source only once.
   - The distance check prevents duplicate queue entries.

6. **Disconnected graph**
   - Vertices unreachable from every source retain infinity.

7. **Cyclic graph**
   - Works normally because discovered vertices are not enqueued again.

8. **Directed graph**
   - Follow only outgoing edges.
   - The BFS logic remains unchanged.

9. **Equally close sources**
   - A vertex may have the same minimum distance from multiple sources.
   - Its distance is still correct regardless of which source discovers it first.

## 8. Important Distinction

There are two different problems:

**Problem A: Minimum distance from any source to every vertex**

Use Multi-Source BFS.

\[
dist[v] = \min_{s \in Sources} dist(s,v)
\]

**Problem B: Distance from every source to every vertex separately**

Run BFS independently from each source, or use an appropriate all-pairs shortest-path algorithm.

Do not confuse these two problem statements.

## 9. When Does Multi-Source BFS Work?

Multi-Source BFS guarantees minimum distances when every edge has equal weight.

| Graph type | Algorithm |
|---|---|
| Unweighted graph (all edges cost 1) | Multi-Source BFS |
| Edge weights are 0 or 1 | Multi-Source 0-1 BFS |
| Non-negative weighted graph | Multi-Source Dijkstra |
| Negative edge weights | Bellman-Ford-based approach, subject to negative-cycle conditions |

## 10. Quick Recall

- Multiple starting vertices → Multi-Source BFS.
- Initialize all distances to infinity.
- Set all source distances to 0.
- Enqueue every source before starting traversal.
- Expand all sources simultaneously.
- Update a neighbor only if its distance is infinity.
- First discovery gives the minimum distance from any source.
- Unreachable vertices remain infinity.
- Same O(V + E) time complexity as ordinary BFS.
